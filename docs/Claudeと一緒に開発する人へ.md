# ビジカレアプリを Claude と一緒に開発する人へ

このリポジトリは、Claude（Cowork／デスクトップアプリ）で作業する前提で整えてあります。
フォルダを Claude に接続すると `CLAUDE.md` が自動で読み込まれ、Claude は規約に沿って動きます。
ここでは「最初の1回」と「毎回の流れ」だけを書きます。

---

## 0. 届いている招待を承諾する

3通届いているはずです。すべて承諾してください。

| どこから | 何のため | 権限 |
| --- | --- | --- |
| GitHub | コードの置き場所 | Write（書き込み） |
| Vercel | 動作確認用の画面を見る | Viewer（閲覧） |
| Supabase | 開発用データベースの中身を見る | Developer |

Supabase の招待リンクは **24時間で失効**します。切れていたら二宮まで連絡してください。

## 1. 最初の1回だけやること

### 1-1. リポジトリを手元に持ってくる

Mac の「ターミナル」アプリで、順に実行します。

```bash
cd ~
git clone git@github.com:ninomiyalisting-glitch/accel-business-college.git
cd accel-business-college
npm install
```

`git clone` で失敗する場合は、GitHub に SSH 鍵が登録されていません。
Claude に「GitHub 用の SSH 鍵を作って登録する手順を教えて」と聞くと案内してくれます。

### 1-2. `.env.local` を置く

二宮からパスワードマネージャーの共有で `.env.local` が届きます。
中身はそのまま、`accel-business-college` フォルダの直下に `.env.local` という名前で保存してください。

**このファイルは Claude に読ませないでください。** チャットに貼るのも、Claude に「中身を見て」と頼むのも不要です。
Claude が作業するのに鍵の中身は要りません。`.gitignore` に入っているので、コミットされることもありません。

### 1-3. 動くか確かめる

```bash
npm run dev
```

ブラウザで http://localhost:3000 を開いて、トップページが出れば準備完了です。
終わるときはターミナルで `Ctrl + C` を押します。

### 1-4. Claude にフォルダを接続する

Claude デスクトップアプリで新しいチャットを開き、「フォルダを追加」で `accel-business-college` を選びます。
これだけで `CLAUDE.md` が読み込まれます。最初に次のように話しかけると、噛み合いが早いです。

> このリポジトリの CLAUDE.md と docs/共同開発のはじめ方.md を読んで、開発の決まりを把握してください。

## 2. 毎回の流れ

作業は必ずこの順番です。Claude に頼むときの言い方の例も添えます。

**① 最新を取り込んで、作業ブランチを切る**

> `git pull origin main` してから、`feat/◯◯` というブランチを切ってください。

◯◯ は作業の中身が分かる英単語にします（例：`feat/event-filter`）。

**② 直したいことを伝える**

> イベント一覧に、カテゴリーで絞り込むボタンを足してください。

Claude が該当ファイルを探して直します。手元の `npm run dev` の画面で確認できます。

**③ ビルドを通す**

> `npm run build` を実行して、エラーが無いことを確認してください。

型エラーはここで出ます。**これが通らないものは push しません。**

**④ ステージングに出して確認する**

> 作業ブランチをコミットして push し、staging ブランチにもマージして push してください。

数分待つと https://stg.college.accel-dash.com に反映されます。
ステージングは Slack でログインでき、本番と同じ画面構成で、データだけが空です。

**⑤ プルリクエストを作る**

> main に向けたプルリクエストを作ってください。変更内容の説明も書いてください。

あとは二宮がレビューして `main` にマージします。**マージされた時点で本番に出ます。**

## 3. Claude に守らせること

`CLAUDE.md` に書いてあるので Claude は基本的に守りますが、次のことを Claude が提案してきたら、断ってください。

- `main` に直接 push する
- 本番のデータベース（Supabase の `ninomiya@…'s Project`）に SQL を流す、データを消す・書き換える
- `.env.local` の中身を表示する、鍵をチャットに貼る
- `SUPABASE_SERVICE_ROLE_KEY` をブラウザ側のコード（`"use client"` のファイル）で使う
- メンバーに通知が飛ぶ変更（Slack 通知など）を、相談なしに本番へ出す

逆に、Claude が「本番に影響するので二宮さんに確認してから進めましょう」と言ったら、それは正しい動きです。

---

## 4. ステージングでできること・できないこと

| 項目 | ステージング |
| --- | --- |
| Slack ログイン | できる（ログインした時点で自分のアカウントが作られます） |
| 記事・イベント・写真・ポイント | 空の状態。テスト用に自由に作って構いません |
| チャット機能 | **エラーになります**。本番の Slack へ投稿が流れるのを防ぐため、Bot のトークンを入れていません |
| データベース | Supabase の `accel-staging` 組織。壊しても本番に影響しません |

## 5. 困ったとき

**`git pull` で衝突した**
→ Claude に「コンフリクトを解消して」と頼めば直してくれます。分からなければ二宮に連絡を。

**Claude が git コマンドで固まる／`.git/index.lock` というエラーが出る**
→ Claude に git を実行させず、Claude には「打つべきコマンドを教えて」と頼み、自分のターミナルで打ってください。こちらのほうが安定します。

**ステージングに反映されない**
→ Vercel の Deployments（https://vercel.com/accelpartners/accel-business-college/deployments）で `staging` のビルドがエラーになっていないか見てください。Viewer 権限で見られます。

**何をしていいか迷った**
→ `docs/共同開発のはじめ方.md` に全体像があります。それでも迷ったら二宮に聞いてください。
